========================================================================
1. QISQACHA
========================================================================

Ushbu repoda mavjud huquqiy korpus va RAG backend saqlangan holda,
fuqarolarga Oʻzbekiston qonunchiligi haqida tabiiy, koʻp bosqichli suhbatda
maʼlumot berishga moʻljallangan veb-ilova yaratildi.

Ilova yangi yuridik javob generatori yoki soxta demo AI yaratmaydi. U mavjud
FastAPI RAG serveriga ulanadi; huquqiy javoblar uchun mavjud retrieval,
modda matnlari, retrieval mode va citation maʼlumotlaridan foydalanadi.
Backend yoki model ishlamasa, interfeys aniq xato va qayta urinish imkonini
koʻrsatadi; uydirma huquqiy javob ko‘rsatmaydi.

Muhim holat: web frontend, TypeScript build va frontend testlari ishga
tushirilib tekshirildi. Backend kodiga tegishli Python testlari va mavjud
RAG regressiya testlari ham oʻtdi. Biroq joriy muhitda FastAPI, Uvicorn,
RAG indeks va model serveri oʻrnatilmagan. Shu sababli serverni ishga
tushirish hamda haqiqiy til modeli bilan huquqiy javob/citation tekshiruvi
bu muhitda bajarilmadi.

2. MAHSULOTNING VAZIFASI VA FOYDALANUVCHI OQIMI
========================================================================

Asosiy oqim:
1. Foydalanuvchi huquqiy vaziyatini oddiy tilda kiritadi.
2. Maxfiy maʼlumotga oʻxshash ayrim identifikatorlar backendga yuborilishidan
   oldin berkitiladi.
3. Frontend oldingi user/assistant xabarlarini shu chat kontekstida backendka
   yuboradi.
4. Mavjud RAG pipeline savolni tahlil qilib, kerakli maqolalarni izlaydi,
   aniq modda soʻrovini deterministik tarzda hal qiladi yoki model orqali
   manbaga tayangan javob tayyorlaydi.
5. Javob Server-Sent Events (SSE) orqali oqimda keladi. Yakuniy SSE bo‘lagida
   keladigan citation va retrieval metadata ham foydalanuvchiga yetkaziladi.
6. Manbalar javobdan ajratilgan kartalarda koʻrsatiladi; lex.uz hujjat
   identifikatori mavjud bo‘lsa, u haqiqiy backend maydoni asosida havolaga
   aylantiriladi.

Interfeysda doimiy ko‘rinadigan izoh:
“Bu AI huquqiy maʼlumot beradi, advokat emas. Javoblar yuridik maslahat yoki
ish natijasi kafolati emas. Qonunning amaldagi tahririni lex.uz’dan tekshiring.”

Ilovada yangi suhbat, saqlangan suhbatni qayta ochish, suhbatni oʻchirish,
barcha tarixni tozalash, javobni nusxalash, xatodan qayta urinish, javobni
toʻxtatish va bir nechta misol savollar mavjud. Enter yuboradi; Shift+Enter
yangi qator kiritadi. Mobil ekranda suhbatlar paneli ochiladi/yopiladi.

Oʻzbek lotin tili interfeys tili. Mavjud RAG promptlari lotin, kirill va rus
tilidagi huquqiy savollar uchun saqlangan; aniqlashtiruvchi savol va xavfsizlik
koʻrsatmalari promptlarga qoʻshilgan. Haqiqiy model javobini ushbu muhitda
sinab boʻlmagani uchun tillararo javob sifati tasdiqlanmagan.

4A. HUQUQ AI ADMIN CONTROL CENTER
========================================================================

Admin konsol:
- Production: FastAPI ilovasidagi /admin va /api/admin/* yoʻllari.
- Development: npm run dev ishga tushirgach http://127.0.0.1:5173/admin.
- Citizen chat / yoʻlida qoladi; admin uchun alohida web/admin/index.html
  entry-point mavjud.
- TypeScript native DOM asosida; dark/light mavzu, collapsible/mobile nav,
  route hash, ⌘/Ctrl+K palette, command search, drawers, notifications,
  keyboard navigation, error/loading/toast va responsive table UI mavjud.
- Admin sahifalar: overview, model health/configuration, usage, prompt
  read-only viewer, evaluation dataset, document explorer, article detail,
  corpus provenance, pipeline status, document intelligence status,
  security posture va infrastructure/GPU.

Maʼlumot va cheklov:
- Hujjat/modda qidiruv real manifest.csv va yuklangan RAG indexdan.
- Source hashes manifest.csv SHA-256 qiymat; article text getArticleDetail
  backend endpointidan. lex.uz URL faqat backenddagi numeric document ID
  mavjud boʻlganda yaratiladi.
- Snapshot UI'da 2026-07 deb bildiriladi; qonun amaldagi holatini lex.uz’dan
  tekshirish kerak.
- Soʻrov, token, citation count, latency va retrieval mode process memory'da
  rolling 24-hour bo‘yicha agregat; prompt yoki answer matni saqlanmaydi.
  Restartda tozalanadi va workerlar orasida bo‘lishilmaydi. SSE yakunlanishi
  alohida hisoblanib, bir stream ikki marta event sifatida yozilmaydi;
  mijoz uzgan stream 499 bilan belgilanadi.
- /v1/models health probe latency model inference latency hisoblanmaydi.
- User analytics, persistent audit log, billing/cost, ingestion queue,
  historical corpus versions va PDF/DOCX processing mavjud emas; UI
  maʼlumotni uydirmasdan “ulanmagan” deb ko‘rsatadi.
- Console read-only; konfiguratsiyani tahrirlash, sync/retry, document upload
  yoki security eventlarni o‘zgartirish tugmalari mavjud emas.

Admin xavfsizligi:
- Admin kirish username, PBKDF2-SHA256 parol xeshi va alohida 32+ belgili
  session-signing secret talab qiladi. Yetishmasa admin API fail-closed
  503 qaytaradi.
- Parol brauzer storage’iga yozilmaydi. Muvaffaqiyatli login 8 soatlik
  imzolangan HttpOnly, SameSite=Strict cookie beradi; HTTPS’da Secure flag
  yoqiladi. Logout cookie’ni server javobi bilan o‘chiradi; sahifani qayta
  ochish cookie amal qilsa login formasini aylanib o‘tadi.
- Admin API so‘rovlari same-origin maxsus header bilan tekshiriladi;
  muvaffaqiyatsiz login uchun limiter process-local.
- Admin login urinishlari uchun 5/60s default process-local limiter mavjud;
  persistent log yoki multi-worker shared limiter emas.
- Admin sahifasida same-origin Content-Security-Policy, no inline script,
  frame denial va no-store API responses mavjud.
- Production HTTPS, aniq CORS_ORIGINS, network edge protection va shared
  rate-limit talab etiladi.

Loglash:
- Toʻliq savol-javob loglari standart holatda oʻchiq.
- Terminalga savol yoki javob matni yozilmaydi.
- CHAT_LOG_ENABLED=true faqat metadata logini ixtiyoriy yoqadi: vaqt,
  retrieval mode, citation soni, soʻrov davomiyligi. Savol, javob, citation
  matni, API kaliti metadata logiga yozilmaydi.
- Production reverse proxy/access loglarida request body yozilmasligi kerak.

Maʼlumotni berkitish:
- Frontend va backendda PINFL/JShShIR, karta, pasport va telefon raqamiga
  oʻxshash keng tarqalgan naqshlarni berkitish qoʻshilgan.
- Redaction oqimi test qilingan.
- Bu regexlar toʻliq DLP yoki shaxsni aniqlovchi barcha maʼlumotlarni
  topadigan kafolatli tizim emas. Noyob formatlar, ish hujjati mazmuni,
  manzil yoki ism kabi maʼlumotlar qolishi mumkin.
- Foydalanuvchiga maxfiy hujjat va keraksiz identifikator yubormaslik
  interfeysda eslatiladi; backend promptlari ham bu maʼlumotni soʻramaslik
  va javobda takrorlamaslikni ko‘rsatadi.

API, CORS, cheklovlar:
- CORS wildcard "*" taqiqlangan; CORS_ORIGINS aniq origin allowlistidir.
- Standart local allowlist: localhost:5173 va 127.0.0.1:5173.
- Brauzer chatiga PUBLIC_CHAT_RATE_LIMIT/IP sliding-window rate limiter
  qoʻshilgan; standart 10 soʻrov / 60 soniya.
- Ushbu limit har bir backend process ichida. Bir nechta worker yoki
  instansiyada umumiy limit uchun reverse proxy/API gatewayda qoʻshimcha
  shared rate limiting talab qilinadi.
- Request hajmi, xabarlar soni va umumiy matn hajmi cheklangan.
- API security headers: X-Content-Type-Options, X-Frame-Options,
  Referrer-Policy, Permissions-Policy; chat va retrieve API javoblari
  cache qilinmaydi.
- Legacy /v1/chat/completions va /retrieve endpointlari TOMARIS_API_KEYS
  server muhitida sozlash bilan himoyalanadi. Public /api/chat/completions
  browser endpointi bu kalitlardan foydalanmaydi. Maxfiy kalitlar hech qachon
  VITE_* env, browser bundle yoki repoga qoʻyilmasin.
- Productionda HTTPS/TLS, reverse proxy, request-size limit, ishonchli host
  siyosati va server secrets boshqaruvi alohida sozlanishi lozim.

Bu himoyalar professional penetration test yoki toʻliq production security
audit oʻrnini bosmaydi.

6. SOZLAMALAR
========================================================================

.env.example namunaviy qiymatlarni beradi. U real secretlarni saqlamaydi.
Python .env faylini avtomatik yuklamaydi; qiymatlarni server muhitiga export
qilish kerak.

Asosiy parametrlar:
- RAG_HOST: FastAPI bind manzili; standart 127.0.0.1.
- RAG_PORT: FastAPI porti; standart 8000.
- RAG_PROXY_TARGET: Vite proxy uchun alohida backend URL (ixtiyoriy).
- VLLM_BASE: OpenAI-mos vLLM serverining /v1 URL manzili.
- VLLM_MODEL: vLLM model/LoRA nomi; standart tomaris.
- MODEL_TIMEOUT_SECONDS: model soʻrovining timeout qiymati.
- QUERY_DEVICE: query embedding qurilmasi; standart cpu.
- BUILD_DEVICE: indeks build qurilmasi. Setup misolida cpu ishlatiladi;
  GPU qurilmasi mos muhitda alohida sozlanadi.
- CORS_ORIGINS: ishonchli frontend originlarining vergul bilan ajratilgan
  roʻyxati.
- PUBLIC_CHAT_RATE_LIMIT: bitta IP uchun oynadagi soʻrovlar soni.
- PUBLIC_CHAT_RATE_WINDOW_SECONDS: rate limit oynasi soniyalarda.
- CHAT_LOG_ENABLED: standart false; faqat metadata logging uchun opt-in.
- CHAT_LOG: metadata yoziladigan server fayli; logging yoqilgandagina kerak.
- VITE_CHAT_ENDPOINT: ixtiyoriy, kalit bo‘lmagan browser API path.
- TOMARIS_API_KEYS: faqat server muhitidagi optional secret; .env.example ga
  secret qiymat qoʻshilmagan.
